# Forest Detail Levels: opt-in, GPU-selected, WebGPU only

A Forest can draw each tree at one of three Detail Levels (Full, Light, Impostor) by its distance from one camera (the one that picks the levels), with a dithered cross-fade between neighbouring levels. Like Material Features (ADR 0008) and Tree Effect channels (ADR 0009) it is opt-in: without `lod` a Forest builds no extra meshes, buffers or bake, and renders exactly as before. The level of every tree is chosen by a compute pass that fills indirect draws per Variant and level, so only nearby trees pay for the full mesh. Compute and indirect draws do not exist on WebGPURenderer's WebGL2 fallback, so there a Forest with `lod` ignores it (one console warning) and draws every tree in full, as today. The rest of the library keeps its WebGL2 promise (ADR 0002).

The Light level is the same Definition and Variant Seed regenerated with fixed reductions (fewer sides and sections, the deepest branch level dropped, larger leaves), which keeps every branch in place because the generator forks its randomness per branch path (ADR 0003). Two reductions differ from that plain rule. A Definition with a single branch level (or an empty deepest one) has no level to drop: its Light level halves the leaves per branch instead and enlarges them to keep the leaf area. And the Light level keeps only about half of the Fruit (a stable pick per Fruit), besides coarser Fruit: low-poly Fruit (a nut, say) cannot lose faces, so thinning is the only way every bundled species gets fewer Fruit triangles at Light. Impostors are hemi-octahedral (frames only cover the upper hemisphere, from the horizon to straight above; a view from below uses the horizon frames), since a Forest is seen from above its ground, baked lazily with the app's renderer the first time the Forest is drawn, always at Growth 1, and store per texel not just colour and normals but the leaf's Season data and the Material Feature inputs. That lets a far tree follow Season (leaf colour, leaf drop, blossom) and live Material Feature tuning without a rebake. A tree that is not fully grown never becomes an Impostor.

## Considered Options

- **CPU buckets (a JS loop sorting trees into per-level instance lists each frame)**: works on both backends, but costs a per-frame loop over every tree and uploads. Rejected in favour of compute, accepting no Detail Levels on WebGL2.
- **GPU only (every level draws every tree, the vertex shader collapses the wrong ones)**: rejected. Every tree still runs the full mesh's vertex shader, so little is saved.
- **Dropping WebGL2 for the whole library**: rejected for this feature. It would break ADR 0002 and the README for every app, not only the ones that use Detail Levels.
- **Mesh decimation for the Light level**: rejected. It breaks the per-vertex Growth, Wind and Season attributes.
- **Impostors baked offline into files**: rejected. They would not follow a live Definition and could drift from the Seed.
- **Impostors tinted only, or scaled by Growth**: rejected. A bare winter forest would keep full far crowns, and a young tree is not a scaled-down old one.

## Consequences

The backend is only known on the Forest's first render: three hands the renderer to the Forest's meshes while drawing them, after that frame's draw list is made, and in three 0.187 nothing can join a draw list that is already made or skip a mesh's pipeline build from `onBeforeRender`. Building the Detail Level meshes up front would therefore compile and draw them on the WebGL2 fallback too, breaking "exactly as without `lod`" there. So on WebGPU the first frame draws every tree in full (one full-cost frame), the Detail Levels take over on the next frame, and `lodReady` (which resolves once the Impostors are baked) is how an app avoids showing that switch; on the WebGL2 fallback `lodReady` resolves on the first render rather than at once.

A tree's Tree ID stays `block base + slot`: the instance shaders read the slot through the per-level index list, not from `instanceIndex`. Shadow passes and extra cameras reuse the levels that camera chose. Until the bake finishes, far trees draw at the Light level. Impostor atlases cost GPU memory per Variant, in two render targets: the tree (colour, normals and Season data, plus the Material Feature inputs when a feature is on) and the wood alone in colour and normals, shown where leaves have dropped. At the default 2048² each RGBA8 atlas with mipmaps is about 21 MiB and each render target's depth buffer 16 MiB: about 139 MiB per Variant, 160 MiB with Material Features. Four RGBA8 attachments is WebGPU's default per-pass limit, which the tree layer reaches with Material Features on. Painterly (ADR 0014) adds a paint atlas to the tree layer (the painted Leaf Masses' place on the crown gradient, per-mass random and gaps): 160 MiB per Variant on its own. With Material Features as well the tree layer has five channels, so it is split into passes of at most four attachments, each its own render target drawing the tree again (colour, normals, Season data and features, then the paint): seven atlases and three depth buffers, about 197 MiB per Variant, and one more bake pass per Variant.
