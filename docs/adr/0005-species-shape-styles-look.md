# A Species describes shape once; a Style turns it into a Tree Definition

Each Species (Oak, Birch, Douglas Fir, ...) is authored once as Style-neutral data: Stems, branch levels with Crown Shape curves, foliage as a Leaf Type with a density and real-world size, bark as a Bark Type with a colour, optional Fruit, Season Profile and Wind. A Style is a pure function that turns a Species into an ordinary, complete Tree Definition: it chooses shading, polygon detail, textures, how the Leaf Type is drawn (clumps, puffs, needles, textured cards or, in Painterly, clumped Leaf Masses of painted spray cards, with its own leaf count and size) and how the Bark Type is drawn (a colour + normal texture pair in realistic, a painted texture in Painterly, colour only otherwise). We rejected hand-authoring every Species in every Style (28 × 4 Definitions for the four built-in Styles, low-poly, stylized, realistic and painterly, that drift apart) and storing per-Style overrides inside each Species, because adding a Style or a Species should cost one piece of work, not one per pair.

## Consequences

The existing `broadleaf` and `conifer` Definitions of each Style stay as they are, so current apps and screenshots don't change; Species are an additional way in. The generated Tree Definition remembers its Species, Leaf Type and Bark Type, so the Tree Editor can apply a different Style later. A Style's mapping is code, so how a Species looks in a Style can change between library versions unless the result is exported as a Tree Definition.

Painterly, added later as the fourth Style, cost one Style module and no change to any Species, as intended. It is also the one exception to "a Style only chooses the look": it compresses every Species' height into 2–4 m for top-down games ([ADR 0013](0013-painterly-compresses-tree-heights.md)); the shape itself is still the Species'. Its Leaf Masses are described in [ADR 0014](0014-painterly-leaf-masses-are-clumped-spray-cards.md).
